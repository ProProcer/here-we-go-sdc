# Private Role 3 review menu

Double-click **`Review Role 3.cmd`** in the repository folder on your laptop.
It opens a private Windows desktop app; nothing is hosted publicly and no web
server is started. The launcher uses Python 3.12 with Tkinter and the project's
pinned Pydantic dependency through `uv`.

## Your daily steps

1. Click **Load latest GitHub report**. The app uses your existing Git/GitHub login
   to download the most recent retained report from a completed daily run. A
   failed run may still have useful saved results; the run status stays visible.
2. In **Sources**, select an article. Read its summary, **What to check**, exact
   supporting quotes, AI quality checks and study-comparison limitations. The
   **Open original source** button permits only configured research-publisher URLs.
3. Click **Approve**, or enter a short review note and click **Reject**. Approval
   is bound to the current review and re-fetches the source to detect changed text.
   It approves the source only, not every finding or a numerical skill effect.
4. Switch to **Skill connections**. Read the proposed connection and its conditions.
   Approve or reject it separately. Approval stays disabled until the source is
   approved and the mapping passed its evidence checks. **All** also shows cached
   negative assessments; **Needs review** focuses on actionable items.
   **No connection found** means the AI found no supported link to that skill;
   **Insufficient evidence** means the stored findings cannot establish a link.
   Neither is a positive connection you can approve. **Source approval needed**,
   **Check flagged**, and **Check failed** explain other approval blockers. Select
   an item to see the specific reason above its evidence summary. Saving source
   approvals to GitHub does not automatically approve skill connections.
5. Use **Ask AI to check again** when a review is questionable or failed. It targets
   only the selected source, or the selected skill/article pair. It uses the
   [bounded model fallback policy](ROLE_3_MODEL_FALLBACK.md), preserves history,
   and never grants approval. Failed rechecks are shown as failures with the prior
   assessment; they are not presented as successful fresh reviews.
6. Click **Save to GitHub** after your decisions. This commits and pushes only the
   review-decision files and their referenced evidence records on `main`. The
   scheduled workflow can then read your decisions. The app keeps unsaved changes
   locally and asks you to save them before loading another report.

You can filter by decision and search by article or skill. Enter your reviewer
name for the audit record. A review note is required for rejection and can also
explain an approval. You can revise a decision from **Approved**, **Rejected** or
**All**; the prior decision is retained in its audit history.

## AI key and GitHub login

Loading saved reports and reviewing evidence do not call Gemini. AI rechecks need
`GEMINI_API_KEY` in the launch environment, or you can click **AI key…** and enter
the key in a masked field. That value stays only in the current app process and
is cleared from the entry after submission. It is not written to a file or a
commit. The GitHub Actions secret cannot be downloaded back into the app.

GitHub download/publish uses the existing Git credential helper for the exact
`ProProcer/here-we-go-sdc` repository. The app does not display or persist the
credential. Artifact download explicitly separates GitHub authentication from
the signed blob-host request and refuses unexpected hosts, paths and archive
entries. It does not follow arbitrary links generated by an AI.

## Saved data and limitations

The private working copy and menu state live in **`.role3-review/`**, which is
gitignored. Review notes and reviewer names are intentionally written to the
repository's decision audit files when you decide, and published only when you
click **Save to GitHub**. Neither identity nor review notes are sent in AI recheck
packets. The cloud schedule remains daily at 09:00 MYT while your laptop is off.

Publishing uses an explicit file list and `git commit --only`; unrelated staged
or modified work is excluded. If the branch is not `main`, the remote differs,
GitHub rejects the push, or your Git login is unavailable, the app keeps your
local decisions. Ask the assistant to sync the branch or resolve the Git issue,
then use **Save to GitHub** again. It never force-pushes or resolves conflicts
by discarding work. The app is an owner-operated tool, not a multi-user authenticated
review service; reviewer labels remain self-declared audit labels.

The menu does not change the accepted finding ledger, occupational ratings,
personal fit or numerical learning priorities. Approved conditional mappings are
available through the existing shared skill-evidence lookup. Finding admission
and numerical adjustments remain separate reviewed steps. Full catalog mapping
continues in bounded batches and its coverage/backlog counts remain visible.

You can also launch it from a terminal:

```powershell
uv run --no-project --python 3.12 --with pydantic==2.12.3 python -m src.intelligence.review_menu
```
